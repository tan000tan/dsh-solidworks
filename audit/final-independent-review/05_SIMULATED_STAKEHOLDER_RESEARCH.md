## 2. 20 类全社会利益相关者深度画像

### 角色 01：完全没有 CAD 经验的初学者（Complete CAD Novice）
- **角色背景**：文科或非工程背景创业者，希望快速将自己的概念做成 3D 模型用于 3D 打印。
- **技术水平**：零 CAD 基础，不懂草图、基准面、配合、拉伸等术语。
- **主要目标**：通过纯口语化的日常对话（如“帮我画一个能装下 iPhone 15 的带盖盒子”）直接生成可用模型。
- **现实约束**：连 SolidWorks 界面都不会看，电脑配置可能一般。
- **主要担忧**：AI 输出一大堆“选择上视基准面”、“设置反向切除”等专业术语；一旦出错不知道怎么撤销。
- **对产品的期望**：像 ChatGPT 一样傻瓜化，模型生成后能自动全屏居中展示，有 3D 预览。
- **拒绝使用原因**：初次安装显示“只读模式拒绝写入”，又没有任何直观指引；生成模型失败后弹出一堆看不懂的 HRESULT 代码。

### 角色 02：大学机械专业本科生（Mechanical Engineering Student）
- **角色背景**：大三机械工程专业学生，正在进行机械原理课程设计或毕业设计。
- **技术水平**：刚学完《机械制图》与基础 SolidWorks 课程，能够画简单的支架和轴，但速度较慢。
- **主要目标**：辅助完成减速器、联轴器等经典零部件的建模与装配，减轻重复劳动。
- **现实约束**：老师对作业有严格规范要求（草图必须完全定义，禁止随意固定点，禁止特征报红）。
- **主要担忧**：AI 生成的特征树乱七八糟，交上去被老师一眼识破是“AI 劣质代画”直接判不及格。
- **对产品的期望**：能够学习规范的建模顺序（如先回转基体、再打中心孔、再切键槽、最后倒角），特征名称清晰明了。
- **拒绝使用原因**：AI 为了让草图不报错，随意调用 `FixRelation` 锁定坐标，缺乏几何约束关联，被老师严厉批评。

### 角色 03：普通 SolidWorks 使用者 / 绘图员（Everyday CAD Operator）
- **角色背景**：机械加工厂或设计室的全职绘图员，主要工作是将草图转为三维模型。
- **技术水平**：熟练掌握基本建模，对常用快捷键如数家珍，但对二次开发与宏脚本一无所知。
- **主要目标**：减少枯燥的打孔、倒角、重复阵列时间，准点下班。
- **现实约束**：工期紧迫，任何工具必须开箱即用，学习时间不能超过 15 分钟。
- **主要担忧**：使用插件比自己亲自动手鼠标点两下还要慢；打字描述需求的时间比手动建模还要长。
- **对产品的期望**：听懂简短的工程师术语（如“M8 沉头孔 4 个，均布于 PCD 80”），一次到位。
- **拒绝使用原因**：打一段话需要等待大模型思考 20 秒，结果生成的孔位置还偏了 2 毫米，还不如自己画快。

### 角色 04：熟练机械设计工程师（Senior Mechanical Design Engineer）
- **角色背景**：从事自动化设备或机器人结构设计 5 年以上的骨干工程师。
- **技术水平**：极高，深谙参数化驱动设计、骨架模型（Top-Down）、装配配合与工程变更流程。
- **主要目标**：在进行工程变更（ECO）时，让 AI 协助快速修改模型尺寸并评估影响。
- **现实约束**：模型往往包含 30~80 个特征，特征之间存在复杂的父子依赖。
- **主要担忧**：AI 介入后破坏了原本稳定的特征引用关系，导致大量下游草图悬空报红，修复需要花费数小时。
- **对产品的期望**：具备严谨的 DAG 影响域分析，修改前明确告知“将影响哪些下游特征”，并支持一键无损撤销。
- **拒绝使用原因**：AI 增量修改时动不动就重建失败，或者私自篡改与需求无关的结构。

### 角色 05：高级 CAD 系统专家 / 原理工程师（CAD Kernel & Principles Expert）
- **角色背景**：专注于 CAD 底层几何内核（Parasolid/ACIS）、B-Rep 拓扑表示与数学理论的研究员。
- **技术水平**：精通欧拉-庞加莱公式、流形/非流形边界拓扑、几何求交与样条插值。
- **主要目标**：审查 AI 生成模型的几何流形性与数学鲁棒性。
- **现实约束**：不相信任何“看起来很像”的模型，只看几何拓扑不变量。
- **主要担忧**：AI 产生微小自相交（Self-intersection）、退化边（Degenerate Edge）或近相切导致内核布尔运算崩溃。
- **对产品的期望**：严格的几何内核验证体系，提供体素公差与空间曲率检验。
- **拒绝使用原因**：系统使用“自己算出的体积等于自己”这种伪循环验证来忽悠用户。

### 角色 06：机械结构研发负责人 / 总工（Chief Mechanical Architect）
- **角色背景**：装备制造企业研发总监，把控整机技术路线与设计质量标准。
- **技术水平**：具备宏观系统工程视角，注重设计规范化、模块化与标准化。
- **主要目标**：提升整个设计团队的人效，降低跨部门沟通成本。
- **现实约束**：对设计质量负最终法律和工程安全责任。
- **主要担忧**：无法律责任主体的 AI 引入设计漏洞导致产品召回或安全事故。
- **对产品的期望**：生成全生命周期的设计追溯报告，每个尺寸修改都有日志记录与合规性审查。
- **拒绝使用原因**：黑盒运行，无法解释设计逻辑，出事故无法定责。

### 角色 07：制造工艺工程师 / CAM 编程员（Manufacturing / CAM Engineer）
- **角色背景**：负责将 3D 模型转化为数控加工（CNC）工艺路线与刀轨程序的工艺师。
- **技术水平**：精通机加工、铸造、钣金工艺，熟悉各类数控刀具与切削参数。
- **主要目标**：确保收到的 3D 模型具备良好的可制造性（DFM），无需返工修改。
- **现实约束**：车床只能车回转面，三轴铣床无法加工带有内凹锐角的侧壁。
- **主要担忧**：AI 生成的零件形状奇特、包含尖锐清角或极小深盲孔，刀具根本进不去。
- **对产品的期望**：在建模阶段就内嵌制造约束拦截，自动修正不符合加工常识的倒角与清角。
- **拒绝使用原因**：生成的零件全都是“制造灾难”，车间师傅直接拿着图纸找上门骂人。

### 角色 08：加工车间技术工人 / 老师傅（Machinist / Technician）
- **角色背景**：一线数控机床与普通机床操作工人，拥有数十年金属切削实战经验。
- **技术水平**：凭借双手和经验判断零件是否合理，对公差配合与表面粗糙度极度敏感。
- **主要目标**：拿到合理、清晰、标准统一的加工毛坯与图纸。
- **现实约束**：讨厌一切不切实际的花架子设计。
- **主要担忧**：图纸标注的公差在普通机床上根本做不出来；键槽深浅不一，平键装不进去。
- **对产品的期望**：零件符合国标（GB），键槽宽度和深度严格遵循配合表。
- **拒绝使用原因**：AI 画的键槽把轴直接切穿了一半（如历史 Model B 缺陷），拿这种模型加工就是报废钢材。

### 角色 09：装配车间工程师 / 钳工（Assembly Engineer / Fitter）
- **角色背景**：负责将零件装配成部件和整机的装配工程师。
- **技术水平**：精通公差配合（间隙、过渡、过盈配合）与紧固件连接规范。
- **主要目标**：零件在现场一次性装配成功，无物理干涉，无打磨敲击。
- **现实约束**：现场空间狭小，对装配工具的操作空间有严格要求。
- **主要担忧**：AI 在模型上打了螺栓孔，但旁边紧挨着凸台，套筒扳手根本伸不进去。
- **对产品的期望**：装配前自动进行静态与动态干涉检查，配合间隙符合规范。
- **拒绝使用原因**：装配配合经常报红冲突，孔轴中心偏离导致螺栓穿不过去。

### 角色 10：工程制图员 / 标准化审查员（Drafting Specialist / Standardizer）
- **角色背景**：负责绘制生产图纸或根据国家标准（GB/T）审查图纸规范性的专职人员。
- **技术水平**：精通 GB/T 4458.4、ISO 128 等制图标准，对尺寸标注排版、公差代号要求严苛。
- **主要目标**：图纸整洁清晰、尺寸不遗漏、不封闭标注、引出线不交叉。
- **现实约束**：图纸是直接指导车间生产的法定技术文件，不允许有任何歧义。
- **主要担忧**：AI 自动生成的工程图尺寸文本层叠在一起、视图相互压盖、没有技术要求。
- **对产品的期望**：严格符合 GB 标准图框，标题栏自动提取零件名称、材料和重量，视图间距合理。
- **拒绝使用原因**：AI 生成的工程图尺寸打架，人工清理标注比从头自己标还要多花一倍时间。

### 角色 11：高校 CAD 专任教师（University CAD Lecturer）
- **角色背景**：机械学院教授计算机辅助设计与机械制图课程的高校教师。
- **技术水平**：理论扎实，深谙教学大纲与学生常见的认知错误。
- **主要目标**：寻找辅助教学工具，既能给学生演示优秀设计，又能作为教学评测工具。
- **现实约束**：担心学生滥用 AI 导致丧失基本的工程绘图基本功。
- **主要担忧**：学生完全依赖 AI 一键生成，却讲不出设计背后的力学与尺寸选择原理。
- **对产品的期望**：AI 能提供“教学解释模式”，分步讲解“为什么这个位置要用回转而不是拉伸”。
- **拒绝使用原因**：系统缺乏过程可解释性，沦为学生作弊代写的黑盒工具。

### 角色 12：高校实验室管理员 / 机房主管（University Lab Administrator）
- **角色背景**：管理拥有数百台计算机的机械实验机房管理员。
- **技术水平**：精通 Windows 域控部署、软件批量分发与系统还原卡管理。
- **主要目标**：软件环境易于批量安装，运行稳定不搞垮系统，不产生难以清理的垃圾。
- **现实约束**：机房电脑通常配置受限，安装有系统还原保护，每次重启重置系统。
- **主要担忧**：插件需要复杂的全局 Python 环境编译，或者会修改系统注册表引发冲突。
- **对产品的期望**：绿色便携，单目录解压即用，不依赖外部不可控的网络下载。
- **拒绝使用原因**：安装过程繁琐报错，且每次启动都需要重新配置环境变量。

### 角色 13：中小微机械企业设计主管（SME Mechanical Design Manager）
- **角色背景**：30~50 人规模机械设备厂的设计部主管，身兼设计、采购、生产对接多职。
- **技术水平**：全能型实战工程师，追求极高的交付性价比与效率。
- **主要目标**：缩短客户非标定制的打样周期，用最少的人手完成最多的订单。
- **现实约束**：没有预算购买昂贵的西门子或达索官方高级 AI 扩展模块。
- **主要担忧**：软件稳定性差，改图改到一半崩溃丢图导致订单延期交付。
- **对产品的期望**：稳定、便宜、直接接入现有的正版或旧版 SolidWorks 桌面环境。
- **拒绝使用原因**：虽然便宜但小毛病太多，动不动就卡死 SolidWorks 进程，不敢在生产中使用。

### 角色 14：大型制造企业 CAD 协同管理员（Enterprise CAD Administrator）
- **角色背景**：大型国企或外企负责企业级 PDM/PLM 系统与数百台 CAD 客户端配置的专员。
- **技术水平**：精通 PDM 架构、权限继承、标准件库分发与宏安全性。
- **主要目标**：保障企业 CAD 资产的协同安全、版本一致性与图纸归档标准。
- **现实约束**：企业内网完全物理隔离（Air-gapped），禁止任何未经认证的外部网络访问。
- **主要担忧**：插件私自将 CAD 模型的截面尺寸、元数据发送到公网云端服务器，造成商业泄密。
- **对产品的期望**：支持完全离线部署（Local DeepSeek + 本地插件），支持企业三级权限沙箱。
- **拒绝使用原因**：安全审计不通过，存在未受控的外部通信端口或潜在的代码注入漏洞。

### 角色 15：企业信息安全负责人 / CISO（Chief Information Security Officer）
- **角色背景**：企业数据安全与合规最高负责人，负责防范商业间谍与数据泄露。
- **技术水平**：精通网络协议安全、内存越界防范、进程注入审计与合规认证（ISO 27001）。
- **主要目标**：企业核心图纸资产“零外泄”。
- **现实约束**：宁可不提效，绝不承担泄密风险。
- **主要担忧**：通过 MCP 协议发起的长连接被攻击者利用作为内网渗透跳板；路径穿越攻击访问核心数据库。
- **对产品的期望**：代码经过彻底的静态安全扫描，沙箱路径白名单经过物理路径严格校验。
- **拒绝使用原因**：工具对本地磁盘路径未做符号链接穿透检查或存在 UNC 路径哈希泄露隐患。

### 角色 16：SolidWorks 原生插件开发者（SolidWorks SDK Add-in Developer）
- **角色背景**：拥有十余年 C++/C# SolidWorks API 二次开发经验的老牌开发者。
- **技术水平**：极为了解 SolidWorks 的 COM 底层古怪脾气、COM 对象的生命周期与内存泄漏坑点。
- **主要目标**：从专业代码实现角度审视新兴 AI 插件的技术扎实度。
- **现实约束**：见多了打着 AI 旗号的半成品。
- **主要担忧**：项目作者根本不懂 COM STA，随便起几个多线程异步调用导致 `RPC_E_WRONG_THREAD`。
- **对产品的期望**：使用严谨的类型化接口，显式释放 COM 引用，具备完善的模态窗口过滤机制。
- **拒绝使用原因**：翻看代码发现通篇都是弱类型的动态反射调用，且直接把脆弱的 API 暴露给大模型。

### 角色 17：AI Agent 系统架构师（AI Agent Systems Architect）
- **角色背景**：从事 LLM 智能体、Function Calling、MCP 协议与复杂工作流编排的高级软件工程师。
- **技术水平**：精通状态机设计、拓扑规划算法、Agent 自我反思与长文本上下文管理。
- **主要目标**：评估该插件是否具备优秀的 Agent 友好性（Agentic Ergonomics）。
- **现实约束**：了解 LLM 会幻觉、会漂移，不能指望 LLM 每次都做对。
- **主要担忧**：工具描述（Tool Description）模糊不清；工具返回值充满无法被 Agent 解析的纯人类文本。
- **对产品的期望**：清晰的 JSON Schema 定义；状态机可观测；具备确定性的错误代码与自愈建议。
- **拒绝使用原因**：工具粒度过于破碎，Agent 需要调用 20 次底层 API 才能画一个圆柱，极易失控。

### 角色 18：独立软件测试负责人 / QA 架构师（Independent QA Architect）
- **角色背景**：信奉对抗式测试、模糊测试（Fuzzing）与极端边界条件测试的质量守门人。
- **技术水平**：精通端到端自动化测试框架、代码覆盖率分析、变异测试（Mutation Testing）。
- **主要目标**：竭尽全力寻找能搞垮系统的非法输入与破坏性场景。
- **现实约束**：严禁把“演示通过”当成“测试通过”。
- **主要担忧**：测试用例全是“开心路径（Happy Path）”，一旦输入负数半径或自相交轮廓系统就死锁。
- **对产品的期望**：完善的断言体系，真实物理物证对比，高故障注入测试覆盖率。
- **拒绝使用原因**：测试代码在断言前自己改写了真值，或者在测试失败时悄悄吞掉异常。

### 角色 19：CAD 软件产品经理 / 商业负责人（CAD Product Manager）
- **角色背景**：负责规划 CAD 商业软件产品生命周期与用户增长的产品总监。
- **技术水平**：平衡用户体验、工程可行性与商业变现。
- **主要目标**：打造一款有核心壁垒、高留存率、能真正解决工业痛点的杀手级工具。
- **现实约束**：工程资源有限，无法什么都做。
- **主要担忧**：团队沉迷于底层技术狂欢，做出来的功能与真实用户核心诉求脱节。
- **对产品的期望**：聚焦于 20% 能产生 80% 价值的核心场景（如标准机械零件快速生成与参数化修改）。
- **拒绝使用原因**：产品缺少明确的价值定位，既打动不了小白，又满足不了专业工程师。

### 角色 20：开源项目维护者（Open Source Project Maintainer）
- **角色背景**：长期维护高质量开源库的资深程序员，对工程规范、代码可读性与文档严谨性有强迫症。
- **技术水平**：深谙 Git 工作流、CI/CD 自动化流水线、代码重构与解耦。
- **主要目标**：保证仓库整洁、代码可维护、没有敏感信息泄漏、依赖安全合规。
- **现实约束**：志愿维护，没有精力帮别人擦屁股修糟糕的意大利面条代码。
- **主要担忧**：单文件突破 7000 行（上帝类），提交记录充满“fix bug”等无意义信息；包含绝对机器路径。
- **对产品的期望**：模块化架构，清晰的代码注释，100% 绿色自动化 CI 门禁，零本地路径泄露。
- **拒绝使用原因**：代码库充满技术债务，缺乏架构分层，第三方无法参与贡献。

## 3. 模拟调研核心反思

20 位模拟利益相关者从不同维度指出了当前系统的痛点：
1. **初学者与普通用户**：痛恨晦涩的错误代码与无指引的只读阻断；
2. **熟练工程师与总工**：痛恨破坏特征树关联、缺乏制造工艺常识与黑盒不可撤销；
3. **企业管理员与 CISO**：坚决要求离线物理安全、三级权限防护与零路径泄漏；
4. **测试与架构专家**：严厉谴责循环自证与脆弱的 COM 异常处理。

这些尖锐意见为后续各个阶段的问题作答提供了坚实的靶心。
