## 一、执行概述与发布背景

`dsh-solidworks` 是 DeepSeek Harness (DSH) 插件生态中用于自动化驱动本机 SolidWorks 桌面版的工业级 CAD 插件。

在 `v0.3.0` 候选版本审查中，独立安全审计发现并指出了若干发布阻断级（P0）与核心产品化（P1）缺陷：
1. **P0 人类审批假面漏洞（AI 自授权漏洞）：** 历史代码允许通过在 MCP 工具参数中传递 `confirmedByHuman: true` 标记获得高危写操作授权。由于 MCP 工具参数由 AI 模型直接构造，恶意或幻觉模型可随意伪造该布尔值自签发授权，突破人机安全边界。
2. **P1 宿主 Python 运行环境污染隐患：** 历史自动自举逻辑在检测到外部 Python 缺少 `mcp` 或 `pywin32` 时，存在向宿主全局 Python 或 DSH Primary Runtime 直接执行 `pip install` 的风险，破坏宿主环境纯净性。
3. **P1 工具计数统计口径歧义：** 历史文档中存在“19 READ + 26 WRITE + 26 HIGH = 71 个工具，但清单声称 73 个工具”的描述矛盾。
4. **P1 测试与打包一致性要求：** 必须保证最终分发的安装包（ZIP 与 TGZ）与实测通过的代码完全同源、绝对路径零泄漏、哈希唯一可追溯。

基于上述问题，本轮任务严格遵循最高执行标准，完成了全部代码级深度整改、18 项极端安全对抗测试、专属 Runtime 隔离验证、真实 SolidWorks 2026 SP4.1 几何物理闭环实机验证，构建了正式发布包并完成了全量独立反向验收。

## 二、核心缺陷整改与技术实现

### 2.1 P0 人类审批体系重构：零信任 HMAC-SHA256 票据挑战响应机制
- **彻底废除 `confirmedByHuman` 参数：** `lib/policy.js` 与 `lib/index.js` 全面移除任何基于普通布尔参数的放行逻辑。
- **内存级随机私钥隔离：** 插件启动时在 Node.js 受保护内存空间内生成 32 字节高熵私钥（`#secretKey`），绝对不通过任何 MCP 接口、错误日志或调试信息暴露。
- **动态挑战生成（Challenge Issuance）：** 未经授权的高危调用立即触发 `CONFIRMATION_REQUIRED`，并在安全门禁处签发唯一挑战对象：
  - 挑战标识符：`challengeId`（`chal_<random_16bytes>`）
  - 操作工具：`tool`
  - 参数指纹：`canonicalArgs` 规范化 JSON 的 SHA-256 摘要（`digest`）
  - 目标路径列表：`targetFiles`
  - 会话标识：`sessionId`
  - 有效期：`expiresAt`（TTL = 120 秒）
- **可信验签与单次消费（Single-Use Verification）：**
  - 授权凭证格式：`ticket = HMAC-SHA256(secretKey, `${challengeId}:${tool}:${digest}:${sessionId}`)`
  - 验签流程：使用 `crypto.timingSafeEqual` 防止时序侧信道攻击；校验通过后立即销毁该挑战，杜绝重放攻击。
- **对抗测试验证：** 编写并运行 `tests/approval_security_adversarial_test.mjs`，覆盖 18 种攻击向量（伪造凭证、篡改参数、凭证重放、过期滥用、跨会话攻击、工具替换、并发竞争、路径篡改等），**18/18 全部通过（100% Fail-Closed）**。

### 2.2 P1 Python Runtime 专属隔离与零污染保证
- **宿主环境纯种子化：** `lib/discover.js` 中的 `tryAutoBootstrap` 函数明确将宿主 Python 和 DSH Primary Runtime 视为“只读种子解释器”。
- **专属目录隔离自举：** 仅允许在 `<pluginRoot>/.venv` 内创建隔离虚拟环境，并使用 `.venv/Scripts/python.exe` 专属绝对路径执行 `pip install mcp>=1.0.0 pywin32>=306`。
- **物理校验确证：** 运行 `tests/runtime_isolation_test.mjs`，物理扫描 `C:\Users\Khalil\.dsh\dsh-runtimes\dsh-primary-runtime`，证明其包列表未发生任何增删，保持 100% 纯净。

### 2.3 工具集完整统计与分类追溯对齐
全面审计并核实实际注册工具，理清工具数量与统计口径：
- **MCP 服务端核心 CAD 工具（71 项）：**
  - `READ`（只读检查，19 项）：如 `solidworks_mass_properties`, `solidworks_health_check`, `solidworks_bounding_box`, `solidworks_list_edges` 等。
  - `WRITE`（常规建模，26 项）：如 `solidworks_new_document`, `solidworks_create_basic_part`, `solidworks_sketch_and_extrude`, `solidworks_fillet` 等。
  - `HIGH`（高危/持久化，26 项）：如 `solidworks_save_document`, `solidworks_close_documents`, `solidworks_export_active`, `solidworks_pack_and_go` 等。
- **DSH 宿主策略与运维工具（2 项）：**
  - `solidworks_status`：环境诊断与运行状态探针。
  - `solidworks_confirm`：高危操作可信票据验证与授权门禁。
- **总计：** 71 + 2 = **73 项完整工具**。在 `dsh-plugin.json`、`lib/policy.js`、`tests/package.test.js` 与用户文档中实现 100% 精确统一。
